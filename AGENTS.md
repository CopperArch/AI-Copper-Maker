# AI Copper Maker — dev context

Local LLM coding studio (FastAPI single-file backend + single-file frontend).
- **Run (Docker-only since 2026-09-20)**: the app is a single Docker container — `ai-coppermaker` (image `ai-copper-maker:latest`), `network_mode: host`, live bind-mounting `~/AI-Copper-Maker:/app` + `~/.config/ai-copper-maker`. `restart: unless-stopped` → auto-starts at boot. Access http://localhost:8081. Restart with `docker restart ai-coppermaker`; rebuild with `docker compose build` (the image only supplies Python packages — code and state come from the bind mounts).
- **No host systemd service**: the old `coppermaker.service` (host venv on 8081) fought the container for port 8081 and was crash-looping — it has been stopped + disabled and is NOT to be re-enabled (`docker` owns 8081 now). `docker-compose.yml` is the canonical deployment file (host network, host ollama; no compose `ollama` service to avoid a 11434 clash).
- **Model server**: `ollama-serve.service` (user install, ~/.local/share/ollama-user; host 11434 — the container reaches it via `OLLAMA_HOST=http://localhost:11434`). llama.cpp on 8080, LM Studio on 1234. Default model lives in gitignored `config.json`.
- **Deploy**: git push origin master.
- **Auth**: gh CLI (account CopperArch). Never add co-author trailers or AI-assistant references to commits; local git identity in this repo is `CopperArch <143160503+CopperArch@users.noreply.github.com>` — always go through a branch → PR → `gh pr merge --squash --delete-branch`, never push raw commits straight to `master` (a direct push in `20a04e7` briefly skipped this and picked up a stale author address as a result).
- **No secrets in git**: config.json, *_accounts.json, google_oauth.json, api_keys.json, release.keystore are gitignored on purpose.

## Session state — 2026-09-17 (post-REV-1.2 additions, deployed + committed)

- **Files tab**: Windows Explorer redesign (breadcrumb, back/forward/up, sortable Details columns, per-type SVG icons, dblclick open, right-click context menu, F2 inline rename, Del delete, status bar). Backend added /api/files/mkdir|rename|delete.
- **Models tab**: sectioned Local / Uncensored / Free / Paid (per-Mtok rates from PRICING) + `/api/models/cloud/details`. Update detection: `/api/models/check-update` compares installed digest vs registry manifest digest; "⬆ Update" badge + one-click in-place re-pull; per-build dismiss in localStorage.
- **Context**: always-on auto-compaction inside `_agent_turns` (75% of effective window → fold into model summary via shared `_compact_conv`; local models capped at the loop's num_ctx 16384, cloud at provider windows). Rendered as an expandable divider, not a user bubble.
- **LSP (opencode-style)**: built-in registry (rust / typescript / python / bash; npx-based servers auto-download on first use), config.json `"lsp": true/false or {overrides}` (default ON here, unlike opencode). After edit_file/write_file, the file's diagnostics are appended to the tool result so the model self-corrects. Status at `/api/lsp/status`, shown as chips in Models tab. NOTE: `@app.on_event` handlers never fire — this app uses a custom `lifespan`; boot-time work must go there.
- **Skills/agents library**: `skills/vendor/` (gitignored) holds shallow clones of third-party collections; the lifespan imports every SKILL.md (skill) and */agents/*.md + *.agent.md (agent persona) into gitignored `skills.json` at startup, idempotent by name. `task` tool takes `agent: "<name>"` to run a specialist persona subagent. System prompt shows a bounded priority-ranked directory (80 skills + 40 agents + "N more") so 2.5k+ entries can't flood the 16k window; per-request keyword hint surfaces the 3 best matches. Currently vendored: agent-skills, superpowers, dotnet `skills`, marketingskills, scientific-agent-skills, awesome-llm-apps, awesome-claude-skills, ai-marketing-skills, Anthropic-Cybersecurity-Skills, Cesarjoquin Marketing-Skills, nvidia-skills, gsap-skills, browser-act-skills, expo-skills, wondelai-skills, openskills, finance-skills, blader humanizer, supabase-agent-skills, binance-skills-hub (+ humanizer_academic vendored in-tree at skills/humanizer_academic). `private-gpt` was cloned too but contains no skill files (it's an application) — nothing importable. To add more: `git clone --depth=1 <url> skills/vendor/<name>` then `systemctl --user restart coppermaker`. Name collisions across repos resolve first-imported-wins by _VENDOR_ORDER.
- **humanizer_academic** (MIT, github.com/matsuikentaro1/humanizer_academic): full skill registered as builtin for on-demand "humanize this text"; a distilled core auto-runs on every prose save (write_file/edit_file on .md/.txt/.rst/.tex) before the file hits disk. config.json `"humanize_on_save": false` disables.
- **LM Studio**: setup script at `setup/lmstudio-linux.sh` (macOS: `setup/lmstudio-macos.sh`, Windows: `setup/lmstudio-windows.ps1`). Installs via `curl -fsSL https://lmstudio.ai/install.sh | bash` → `lms` binary at `~/.lmstudio/bin/lms`. Persistence via systemd --user service `llmstudio.service` (auto-starts at login). The `lms` binary path is added to `coppermaker.service`'s PATH so the backend can find it via `shutil.which("lms")`. Never install LM Studio via `pip install lm-studio` or `dnf install lm-studio` — neither works; the correct pip package is `lmstudio` (the Python SDK, not the app) and the correct flatpak app ID is `ai.lmstudio.lm-studio`.
- **llama.cpp**: setup script at `setup/llama-cpp-linux.sh`. Installs `llama-cpp` via `dnf install llama-cpp` (Fedora), auto-detects hardware (ROCm/CUDA/Vulkan/CPU, RAM, threads), downloads a GGUF model, starts `llama-server` on port 8080, and registers a systemd --user service `llama-cpp.service` for auto-start at login. Backend accessed via `LLAMA_CPP_HOST=http://localhost:8080` env var. Models use `llama-cpp/<model_id>` prefix in the frontend. OpenAI-compatible API at `/v1/chat/completions`.
- **OpenCode-style features**: auto-compaction in `_agent_turns` (75% context → fold into summary via `_compact_conv`), plan-first/todo_write agent loop, tool-use pattern matching, MCP support planned.
